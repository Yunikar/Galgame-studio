# Galgame Studio

可视化 Galgame（视觉小说）制作工具：**不写代码**，用节点图把台词、立绘、背景、音乐串成剧情，然后一键导出成别人能直接玩的作品。

- 网页版（zip）：解压后双击 `index.html` 就能玩，也可以传到任意静态托管做成在线链接
- Windows 程序（exe）：生成一个自包含的游戏文件夹，双击 `《作品名》.exe` 即玩

整个项目没有后端：编辑器跑在浏览器里，数据存在 localStorage + IndexedDB。

## 环境准备

| 想做的事 | 需要 |
| --- | --- |
| 跑编辑器（浏览器里用） | Node.js 18+ |
| 导出 Web 版 zip | Node.js 18+ |
| 打包编辑器桌面版 / 导出 exe | 还需要 Rust（1.77+）与 Tauri 2 依赖 |

安装 Rust（只有打桌面包时才需要）：

- Windows：去 <https://rustup.rs> 下载 rustup-init.exe 一路下一步；
  另外确保装了 **Visual Studio Build Tools（含 C++ 桌面开发组件）** 和 **WebView2**（Win10/11 一般自带）。
- macOS：`curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`

装完后验证：

```bash
node -v   # v18 以上
cargo -V  # 只有打桌面包需要
```

> 本仓库已在 Windows 11 + Rust 1.98（stable-msvc）+ VS 2022 环境下完整跑通
> 桌面版与播放器的真实构建，产物均通过启动测试。

## 本地运行编辑器

```bash
npm install          # 第一次需要
npm run build:template   # 编译游戏运行时，拷到编辑器里（导出功能依赖它）
npm run dev:editor   # 启动编辑器
```

打开浏览器访问 <http://localhost:5173>。

> `build:template` 只在 runtime 代码改动后才需要重新跑。不跑它编辑器也能正常编辑，
> 只是点「导出作品」时会提示找不到运行时模板。

其他常用命令：

| 命令 | 作用 |
| --- | --- |
| `npm run dev:runtime` | 单独跑游戏运行时（调试播放器用，端口 5174） |
| `npm run check` | 类型检查 + 冒烟测试（70 项断言，不需要浏览器） |
| `npm run build:editor` | 构建编辑器 |
| `npm run build:runtime:web` | 构建运行时的单文件 Web 版 |

## 打包编辑器桌面版

```bash
npm run build:template   # 导出功能要用
npm run build:desktop
```

产物是**裸可执行文件**（不做安装包）：`editor/src-tauri/target/release/galgame-editor.exe`，
双击即用。首次编译约 8 分钟，之后增量编译很快。

调试模式（热更新）：

```bash
# 终端 1
npm run dev:editor
# 终端 2
npm run tauri:editor dev
```

## 打包游戏播放器（exe）

播放器就是「导出 exe」时被复制进游戏文件夹的那个程序。

```bash
npm run build:player
```

产物：`runtime/src-tauri/target/release/galgame-player.exe`（约 3 MB，复用系统 WebView2）。
脚本会**自动**把它复制到 `editor/src-tauri/target/release/player/` 下——
正是桌面版编辑器寻找播放器的位置，所以跑完这一条，「导出 exe」就直接可用了。

它如何被编辑器找到（按顺序尝试）：

1. 环境变量 `GALGAME_PLAYER_EXE` 指向的路径
2. 编辑器 exe 旁边的 `player/galgame-player.exe`（`build:player` 自动放好）
3. 开发模式下的 `runtime/src-tauri/target/release/galgame-player.exe`

> 没编译播放器时，「导出 exe」会写好游戏文件但提示找不到播放器；
> 此时游戏文件夹里的 `index.html` 依然可以直接用浏览器玩。

播放器的工作方式：启动后读取**自己所在目录**的 `story.json` 与 `assets/`，
所以把 exe 和游戏文件放在一起，整个文件夹拷到任何 Windows 电脑上都能玩。

## 10 分钟做出一个小游戏

下面用内置示例之外的一个小场景，演示完整流程。

编辑器界面一览：

```
┌────────────────────────────────────────────────────────────────┐
│ Galgame 编辑器  [作品名]  新建 打开 保存工程      校验 预览 导出 │
├──────────┬──────────────────────────────────────┬──────────────┤
│ 资源面板  │  场景切换 + 新增节点                  │  属性面板     │
│ 角色     │                                      │ (改选中节点的 │
│ 背景图   │      [台词] → [台词] → [选项]         │  内容)       │
│ 音乐     │                  ├──→ [台词]        │              │
│ 音效     │                  └──→ [台词]        │              │
│ 语音     │                                      │              │
├──────────┴──────────────────────────────────────┴──────────────┤
│ 实时预览：从场景开头 / 从选中节点开始播放                        │
└────────────────────────────────────────────────────────────────┘
```

### 第 1 分钟：起名字

打开编辑器，顶部输入框里把「未命名作品」改成《雨夜的便利店》。

### 第 2~3 分钟：放素材（可选）

左侧点「背景图」→ 上传一张便利店照片；点「角色」→ 新建角色「小雨」，
再点「立绘」上传她的立绘并挂到角色上。

没有素材也能继续，游戏会显示占位图。

### 第 4~8 分钟：摆剧情

中间画布上方点「新增节点 → 台词」，然后在右侧属性面板写内容：

```
[台词·旁白]   晚上十一点，便利店只剩你一个人。
     ↓
[台词·小雨]   「欢迎光临……咦，你怎么才来？」
     ↓
[立绘·小雨]   左侧位置，淡入
     ↓
[选项]        你要说什么？
              ├── 「我来接你下班」 → 走 A 线
              └── 「随便逛逛」     → 走 B 线
     ↓                        ↓
[台词] 「……笨蛋，等很久了。」  [台词] 「哦，那……再见。」
     ↓                        ↓
[结局] 温柔的雨夜             [结局] 错过的雨
```

操作要点：

- 每个节点在右侧面板填写内容；节点之间**按顺序自动连线**，也可以在图上手动拖连线。
- 选项节点有几个选项就能连几条后续，每条线单独走。
- 左上角「背景图」「音乐」等节点负责换场景、换 BGM，插在台词之间即可。
- 想要多场景（比如「便利店」和「雨夜街道」两个画布），用顶部场景条新建，
  再用「跳转场景」节点连过去。

### 第 9 分钟：试玩 + 校验

- 点右上角「实时预览」，直接试玩；勾「从选中节点开始」可以只试某一段。
- 点「校验」：悬空的节点、没连到结局的线路、没选素材的引用，都会列出来，
  点提示可以直接跳到出问题的节点。

### 第 10 分钟：导出

点右上角「导出作品」：

- **网页版（zip）**：得到《雨夜的便利店.zip》，发给朋友，解压后双击 `index.html` 即玩；
  也可以把解压出来的文件夹整个上传到 GitHub Pages / Vercel 等静态托管，变成在线链接。
- **Windows 程序（exe）**：桌面版编辑器里可用，选一个文件夹，得到
  `《雨夜的便利店》.exe` + `story.json` + `assets/`，双击 exe 即玩。

存档（3 个手动存档位 + 1 个自动存档）、文字速度、各种音量、全屏，
玩家都能在游戏右下角自己调。

## 导出格式说明

两种导出共用同一份组装逻辑，产出的游戏目录结构完全一致：

```
《作品名》/
├── index.html      游戏页面（剧本已内联，双击即玩，file:// 协议也能跑）
├── app.js          游戏运行时（已编译的单文件）
├── story.json      剧本数据（纯数据，不含素材二进制）
├── assets/         所有素材文件
│   ├── xxx.png
│   └── xxx.mp3
└── 如何游玩.txt    给玩家看的说明
```

- `index.html` 里内联了一份剧本，所以**不联网、不起服务**也能玩；
  走 http(s) 托管时则会优先读同目录的 `story.json`。
- exe 版播放器启动时用 Tauri 命令读取 `story.json` 与 `assets/`（带路径穿越防护）。

## 项目结构

```
galgame-studio/
├── shared/     共享代码：剧本数据模型、校验规则、节点图工具、内置示例
├── editor/     编辑器（React + React Flow + Zustand）
│   ├── src/lib/        文件读写、导出组装、素材转换
│   ├── src/components/ 资源面板 / 节点图 / 属性面板 / 预览 / 导出弹窗 / 新手引导
│   ├── src/store/      项目状态（含撤销重做）、界面状态、Toast
│   ├── public/runtime-web/  游戏运行时模板（build:template 生成）
│   └── src-tauri/      编辑器桌面版（文件读写全部在 Rust 侧完成）
├── runtime/    游戏运行时（被编辑器内嵌预览，也独立导出）
│   ├── src/engine/     无 DOM 依赖的剧情引擎（推进 / 分支 / 预演 / 存档状态）
│   ├── src/player/     舞台渲染：背景 / 立绘 / 对话框 / 选项 / 特效 / 音频
│   └── src-tauri/      便携播放器（exe）
└── scripts/    build-web-template / make-icons / 冒烟测试
```

关键设计：

- **剧本模型**只有一份（`shared/src/types.ts`），编辑器与运行时引用同一套类型，
  结构永远不会对不上。
- **剧情引擎不碰 DOM**，输入剧本索引和状态，输出下一步事件，
  因此可以在 Node 里直接做单元/冒烟测试（`npm run check`）。
- 素材二进制存 IndexedDB，项目结构存 localStorage，避免 5MB 配额爆掉。
- 编辑器的所有修改都是纯函数变更（`lib/mutations/`），撤销重做栈统一处理。

## 常见问题

**「导出作品」提示找不到运行时模板**
先执行 `npm run build:template`。

**导出 exe 提示找不到播放器**
先执行 `npm run build:player`（会自动把播放器复制到位），再重启编辑器。

**双击导出的 index.html 没反应**
用 Chrome / Edge 打开；素材要和 index.html 在同一个文件夹里，不要只把 index.html 拷出来。

**游戏里的图片显示占位、音乐放不出来**
导出时弹窗会列出「找不到文件」的素材，回编辑器重新上传即可。

**存档丢了**
存档存在浏览器本地，换浏览器、清浏览器数据、file:// 换路径都会丢。exe 版同理（跟随系统）。

**Windows 上第一次 cargo build 很慢**
Tauri 要编译几百个依赖（首次约 7 分钟），属正常现象，之后增量编译很快。
